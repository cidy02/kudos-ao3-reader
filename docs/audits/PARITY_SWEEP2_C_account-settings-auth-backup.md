| Backup import runs immediately with no confirmation | `BackupScreen.kt` import SAF callback (≈74–95) reads the file and calls `repository.importV2ZipBytes(bytes)` with no intermediate confirm step. Android has no equivalent gate on `BackupScreen`. | Picking a backup file on Android starts merging into your library and overwriting app settings the moment you choose the file — there is no “are you sure?” with a summary of what will change. On iPhone you always get a confirmation dialog first. | high |
| Removing a work from a collection is not tombstoned; backup merge re-unions membership | `WorkRepository.removeFromCollection` (`WorkRepository.kt` ≈354–358) only calls `collectionDao.removeWork` + `touchCollection` — never writes a `SyncTombstone` with `WORK_COLLECTION_MEMBERSHIP` (constant exists in `SyncModels.kt:12` but is unused). `BackupMergeService.mergeCollections` always unions IDs: `mergedWorkIds = (existing.workIds + archived.workIDs).distinct()` (≈411–413). `TombstoneIndex` indexes reading-queue memberships and whole collections, but `WORK_COLLECTION_MEMBERSHIP` falls through `else -> Unit` (≈758–778). iOS records `SyncTombstones.recordCollectionMembershipRemoval` on remove and consults `suppressesCollectionMembership` during restore (`KudosBackup.swift` ≈1295–1312; `PersistenceSync.swift`). | If you take a work out of a local collection and later restore an older backup that still lists it, Android can silently put it back in that collection. iPhone remembers the removal so a stale backup does not undo it. | high |
| Account › Preferences is WebView-only; iOS has a full native AO3 preferences editor | Android Overview “Preferences” (`AccountScreen.kt` ≈513–517) calls `onOpenWeb("https://archiveofourown.org/preferences")` — in-app browser only. There is no Kotlin package for preferences load/save. iOS routes `Route.preferences` → `AO3PreferencesView` (`AccountView.swift` ≈455) backed by `AO3Client+Preferences.swift` / `AO3PreferencesActions.swift` / `AO3PreferencesModels.swift` (~1k lines): live form load, in-app edit, authenticated Save, help sheets; password/email/username stay web links. | On iPhone, Account › Preferences is a real in-app form for your AO3 reading/display/warning preferences with Save. On Android the same row just opens AO3’s website in a browser — no native editing, and the URL is the generic `/preferences` page rather than a structured native UI. | high |
| Writing › Series is a static stub; iOS shows the signed-in user’s live series list | `AccountWritingKind.Series` maps to `null` (`AccountUiState.kt` ≈66–68). `WritingTabContent` renders only `EmptyStateCard("Series not available yet", …)` (`AccountScreen.kt` ≈798–803). iOS `writingSections` / `profileSeriesSections` (`AccountView.swift` ≈746–747, 906–941) loads the signed-in profile model and renders `AO3AuthorSeriesSection` (with loading/error/stale-cache states). | Account AO3 lists have no pull-to-refresh (only Retry after failure) | `AccountListViewModel` / `AO3CollectionsViewModel` load once in `init` and again only via explicit `load`/`Retry` (`AccountViewModel.kt` ≈56–74, 99–116). `HubWorksPane` / collections UI have no `PullToRefresh` / swipe-refresh. iOS Account Reading/Activity use `.refreshable { await refreshCurrentTab() }` (`AccountView.swift` ≈208, 248); collections use `.refreshable { await load() }` (`AO3CollectionsList.swift` ≈78). | If you change bookmarks/history/subscriptions on the AO3 website and return to the app, iPhone lets you pull down to reload. On Android the list keeps whatever it fetched earlier until you leave and force a new screen instance or hit Retry after an error. | high |
| Logout does not record a “removal pending” flag if durable session delete fails | `AO3AuthRepository.clearSession` (`AO3AuthRepository.kt` ≈122–126) always sets in-memory state signed-out and calls `sessionStore.delete()` / `cookieStore.clear()`, but `FileAO3SessionStore.delete` (`AO3SessionStore.kt` ≈47–53) ignores `File.delete()` failure and never surfaces it. There is no `AO3SessionRemovalTracking` equivalent. iOS `logout` / clear paths mark `removalTracker.markRemovalPending()` when vault delete fails, and `restoreSession` refuses to restore while `isRemovalPending` (`AO3AuthService.swift` ≈390+, 504–535; `AO3SessionVault.swift` removal tracker). | In the rare case the session file cannot be deleted (permissions, disk glitch), Android can still look signed-out in the UI for this process, but the next cold start may load the old cookies again. iPhone remembers that removal was incomplete and will not re-restore those credentials until delete succeeds. | medium |
| Web login cookie capture drops expiry / path / HttpOnly attributes | `AndroidAO3CookieStore.captureSession` (`AO3CookieStore.kt` ≈15–18) builds cookies only from `CookieManager.getCookie(BASE_URL)` via `parseCookieHeader`, which keeps **name=value only** (≈42–54) and relies on `AO3StoredCookie` defaults (`expiresAtEpochMillis = null`, fixed domain/path). iOS `AO3CookieBridge.captureAO3Cookies` maps full `HTTPCookie` fields (domain, path, expires, secure, httpOnly). Live validation can later merge `Set-Cookie` with real expiry (`AO3SessionValidator.mergingResponseCookies`), but the initial post-login snapshot is metadata-poor. | After you log in, Android saves your session cookies without their real expiry times (and with incomplete cookie attributes). The app mostly still works because it re-checks login with AO3, but it cannot expire stale cookies locally the way iOS can, and reinstalls of cookies into WebView are less faithful to what AO3 set. | medium |
| Custom font import allows only one file per picker trip | Settings font importer uses `ActivityResultContracts.OpenDocument()` (`SettingsScreen.kt` ≈123–124) — single URI. iOS font `fileImporter` sets `allowsMultipleSelection: activeImportAllowsMultipleSelection` (`SettingsView.swift` ≈430–436) and imports each URL. | On iPhone you can multi-select several font files at once when importing. On Android you pick and import one font file per trip to the file picker — more taps for a multi-font library, not a functional break. | high |
