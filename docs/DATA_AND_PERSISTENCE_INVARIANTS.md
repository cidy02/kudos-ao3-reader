# DATA_AND_PERSISTENCE_INVARIANTS.md

Rules that protect user data. Breaking any of these is a regression even if tests pass. Confirmed as of 2026-07-10.

## Never lose

- Each new `ReadingSession` records the start time-zone offset, start progress and spine, read/listen mode and listening rate, active seconds, install-scoped device ID, and counting-rules version. Each gap between activity marks contributes at most 300 seconds; pauses count nothing. Start progress is 0 for an unread work and `nil` for a previously read legacy work without a stored overall fraction; chapter counts never supply it. Old rows keep `nil` for unavailable measurements and default `read` / empty device ID / rules version 0. Never backfill or infer these facts from later position, clock, or device state. The device ID travels on session rows through backup and folder sync, but is never exported as a setting. These keys are additive on backup v8. A sitting ends when the reader closes, except that Read Aloud continuing outside the reader keeps its `.listen` row open until playback stops or tears down (T-535 D4, below).
- A saved work's **EPUB file**, captured or user-edited **download date** (`downloadedAt`), **reading progress** (`readiumLocator`, `lastSpineIndex`, `lastScrollFraction`, `progressModifiedAt`), user flags (`isFavorite`/`isSaved`/`isFinished`, plus `keepInProgressOverride` so an Abandoned undo cannot be re-derived away, and `hiddenFromHistoryAt` — 1ah's Remove from history, a hide marker that never deletes the work and that reading the work again clears in `markProgressModified`), tags, queues, collections, bookmarks, **in-book annotations** (`ReadingAnnotation`: bookmarks/highlights/notes, anchored by a Readium `Locator` string plus a `selectedText` snapshot so the mark survives a dangling anchor), **reading sessions** (`ReadingSession`: which work, when, how long, where it got to — the local log History / Finished / Insights / tag counts / reread count all read; keyed by `SavedWork.id`, not title, and **not** a SwiftData relationship so deleting the EPUB cannot cascade-delete history), **local stars** (`ReadingFavorite`: work / author / fandom / tag, never an AO3 write), and **per-fandom visit watermarks** (`FandomReadWatermark`: raw AO3 tag name, never a parsed title).
- **No network outcome may delete local data.** AO3 404 → set `ao3Unavailable = true`, keep everything (`WorkTags.refreshFromAO3`). The subscriptions scan records a 404 only as `gone` on its own snapshot and never writes or deletes `SavedWork`. 429/403/5xx/offline → keep prior state; list refreshes keep previously loaded content on failure.
- Finishing an un-kept work does not free its EPUB at once: `WorkLifecycle.holdFinishedCopy` stamps `freedAt` and the file waits 60 days in Recently Deleted's "Finished, not kept" section (Restore keeps it downloaded), then `sweepHeldCopies` frees it with the Recently Deleted sweep. Reading, un-finishing or keeping the work releases the hold. Remove Download only clears the keep flag; only Delete (and Privacy's explicit Free up space) removes a file.
- Deletion is user-initiated only. Works, collections, and queues land in **Recently Deleted for 90 days** first (`PreservedWorkService.softDelete` — sets `isPendingDeletion`/`deletedAt`/`permanentDeletionScheduledAt`, records a tombstone, keeps the EPUB). Only `sweepExpired`/explicit "Delete Permanently" hard-deletes (`WorkLifecycle.hardDelete`). Sweep is gated behind `PersistenceOperationGate`. In-book annotations, saved AO3 links (`Bookmark`), named searches (`SavedSearch`), reading sessions, local favorites, and fandom watermarks are the other class: immediate hard-delete plus a signed tombstone, no RD UI. Replace-mode omission of those last three mints the same tombstone (SavedSearch pattern) — but only when the archive carries the key (see "Absent is not empty" below).

## Backups and the sync folder are a complete snapshot (owner, 2026-11-16)

> "backups and sync folders should be a complete snapshot of all the data of the app - everything except login data or cookies" (owner, 2026-11-16, T-541).

- **Carried:** the whole library and every SwiftData record (Recently Deleted included: a work the archive marks deleted restores into Recently Deleted while its window is open, `TombstoneIndex.suppressesResurrection`), EPUBs, fonts, imported originals, pronunciation corrections, writing recovery drafts (`manifest.writingRecovery`), the mail updates list and each account's subscription scan (`manifest.documents`), and every preference: the named `KudosBackupSettings` fields plus `KudosBackupSettings.extras` (allowlisted by `extraKind(for:)`, including comment drafts, Posting As, account shortcuts, recent writing tags, Read Aloud voice and tuning, list layouts, watermarks).
- **Not carried, by rule:** sign-in data (cookies, the AO3 session and username hint, the Keychain, the mail sign-in and its read position `cursor.json`); this device's own wiring (the sync folder's bookmark and stamps, device and tombstone-signing ids and trust, migration flags, crash counters, which voice pack and execution provider this device has, the open tab, onboarding and changelog flags); AO3 politeness timers (Rank Top 100 throttles, `lastTagRefreshAttemptAt`, and the three Retry-After holds `savedSeries.retryAfterUntil`, `followedTags.retryAfterUntil`, `queueSources.retryAfterUntil`: device-local, never in the settings allowlist); a file's own device state (`freedAt`, `remoteEPUBPending`); caches that rebuild themselves (search index, metadata, chapter lengths, reader scratch, cover-art cache, guessed-word log) and the downloadable voice model packs; debug and demo switches. A new stored value goes in one list or the other in the same commit.
- **Newer wins, per value.** A sync replaces a setting, a map entry (each comment draft, each Posting As account) or a pronunciation correction only with a newer one (`SyncedSettingsClock`). A value from a copy without stamps (an older build, Android) is dated by that copy's export and never beats a real edit made on this device. A restore the reader starts still takes the file's values. Drafts and data files are only added or replaced by something newer, never removed by absence.

**Named settings and stamped resets (T-541).** The settings the integration branch added as named fields (embedded cover art, weekly series check, page turn, Read Aloud voice id and name, last-added queue, the nine Reading Insights options) apply by recency like every other setting: a sync takes a value only when its stamp is newer; an explicit restore takes the file's value. A field absent with the sender's own real stamp is a reset there and removes the local value; absent without one is an older build or Android and changes nothing. A field present but undecodable (`malformedNamed`) is neither applied nor taken for a reset, whatever its stamp. The voice id and its name are one setting: the later of their two stamps decides, both apply together, and the result is adopted into the clock (a sync's own cleanup is never a local edit). The voice pair is reset as a pair (one comparison, both cleared), and a pair with an unreadable member is ignored whole. The lane's earlier extras for these keys were never shipped and are not read. A per-list `.arrangement` key this device ever learned stays observed (clock baseline), so removing it sends a reset.

`accentColorHex` is the reader's accent (`#RRGGBB`). Export writes it only when a value is stored. An unchosen device omits the key, so a current build never takes another device's colour from it. Older builds and today's Android still decode a missing key as `#990000` and apply it, so an unchosen device's manifest can still reset their accent — unchanged from before, when export wrote a default instead. Restore skips an absent key and a present `#990000` (any case): that hex is the pre-2026-10-29 default old builds write when nobody chose. Any other present value is applied as stored. A stored `#990000` is read as AO3 Red `#821019`. The stored string is not rewritten. `workSymbolPlacement` (Settings › Appearance › Work Symbols, T-504) follows the same rule: export writes it only when a value is stored, restore applies only a present value this build knows (`beside`, `underTitle`), and an absent or unknown one leaves the local choice. `lastAddedReadingQueueID` is also additive on backup v8: export omits an unset preference, restore applies a valid UUID when present, and an absent or invalid value leaves the local choice unless the sender's own stamp says it was reset there (see the stamped-resets paragraph below). The nine Reading Insights options (`discreetMode`, `hideReadingTime`, `countRereads`, `countReadAloud`, `askAboutUntouched`, `untouchedDays`, `excludedFandoms`, `excludedTags`, `excludedWorkIDs`) are also additive on backup v8: each key is written to `UserDefaults` only when edited, export omits unset keys so an untouched device never clobbers another device's choices on sync/merge, and restore applies present keys by recency; an omitted key changes nothing unless it carries the sender's own real stamp, which is a reset.

## Identity & duplicates

- Identity tiers: **AO3 work ID → canonical AO3 URL → record UUID** — only via `WorkIdentityIndex`. Never write a new matcher.
- No DB-level uniqueness on `SavedWork`; dedup is application-level. `importEPUB` re-checks `existingWork(forSource:)` **after** the awaited download and merges (fill-only) into any match — keep this; it closes the TOCTOU race.
- **Re-acquiring revives**: any acquisition path (save, import, queue add, download) that matches a Recently-Deleted record must `PreservedWorkService.restore` it, never duplicate it or mutate it while hidden.
- Author display text is not an AO3 identifier. Only `AO3AuthorIdentity.route` may drive native profile navigation; anonymous/deleted/guest text and old local imports stay non-navigable.

## Merge rules (backup restore + folder sync share them)

- Timestamp-aware: `incomingWins` = `SyncMerge.shouldApplyIncoming(local:incoming:)`; new records always adopt archive values.
- Booleans (`isFavorite`, `isSaved`, `isFinished`, `isComplete`, `isPendingDeletion`) are `incomingWins`-gated — never OR/AND-merged blindly.
- Tombstones travel in the manifest, merge before conflict resolution, suppress resurrection with a newer-snapshot escape hatch; `restore()` **retracts** the tombstone rather than racing timestamps. In File Merge it does so only for a live archive copy: a work, collection or queue the archive itself marks deleted stays in Recently Deleted, with its tombstone and its deadline.
- Membership removal has tombstones too (`.readingQueueMembership`, `.workCollectionMembership` with composite ID `SyncTombstone.collectionMembershipID`). Deleting an in-book annotation tombstones it as `.readingAnnotation`, so an older archive cannot resurrect it. Saved AO3 links (`.bookmark`), named searches (`.savedSearch`), reading sessions (`.readingSession`), local favorites (`.readingFavorite`), fandom watermarks (`.fandomReadWatermark`), and locally followed tags (`.followedTag`) are the same immediate-delete class: hard-delete plus a signed tombstone at that moment, no Recently Deleted UI, no 90-day clock. Replace-mode omission of those types mints that tombstone too (explicit "Replace Library" only — never folder sync). **Absent is not empty (T-563):** in Replace Library a top-level key the archive does not carry says nothing about those rows — local rows stay and no tombstone is written; only a PRESENT key, even `[]`, replaces that collection. `readingSessions` / `readingFavorites` / `fandomReadWatermarks` decode as optional arrays (`nil` = absent); `collections`, `readingQueues`, `annotations` and `savedSearches` keep non-optional arrays but `KudosBackupManifest.omittedKeys` records which of them were missing, and Replace skips that collection's sweep (soft-delete or tombstone). Every writer passes arrays, so this app always emits all seven keys (`[]` included): an iOS archive behaves as before, and wiping a collection needs an archive that carries it as `[]`. Not affected: `works`, `bookmarks`, `fonts` (required keys, decode fails without them), `readingQueueMemberships` (Replace never sweeps unlisted memberships), `followedTags` / `tagAliases` (already optional, untouched when absent), settings and pronunciations (never delete). Merge restore and Folder Sync reconcile never swept on omission and are unchanged. Android should write the keys it holds (A-541). Followed tag `followedTags` backup arrays omit their manifest key when empty and omit unset optional keys (`tagCategoryRaw`, `tagURLString`, `lastCheckedAt`, `lastSeenWorkID`, `lastSeenPublishedAt`, `seenWorkIDs`), leaving stored tags untouched when an older/Android archive lacks the key.
- Annotations merge by record id under the same `SyncMerge.shouldApplyIncoming` rule; one whose work is absent from the restore is skipped, never orphaned (its anchor is meaningless without the book).
- Restore reindexes each restored work; suppressed works' EPUBs are never written (no orphans from suppression).

## Folder sync safety

- Writes: stage to `itemReplacementDirectory` (same volume) → `replaceItemAt` — the remote package must survive any failed write. Never remove-then-write.
- Reads: skip when coordinated `contentModificationDate` matches the stored stamp (updated after restores AND own writes) — but **never skip while `NSFileVersion` unresolved conflicts exist**.
- All package I/O under `NSFileCoordinator`; conflicts folded by restoring each version then resolving.
- Every upload reads first: `syncUp` is `syncNow`. A manifest published without reading drops what another device added since, and the prune after it deletes that device's files.
- Pruning needs a view of the folder known to be current: the manifest is at its path, its date is readable, and the date equals the stored stamp. **Files and no manifest is not a first write** (older Android builds rename the manifest away for a moment; iCloud may not have downloaded it; an interrupted first sync leaves files without one): write the manifest, prune nothing. Only a folder holding nothing but hidden files is a first write.
- A manifest that is not JSON at all was cut short by a write that died (Android writes its manifest in place). Recover from Android's `manifest.json.bak` when it decodes, write a whole manifest, prune nothing. A manifest that is whole JSON and does not decode is another app version's: it stops the sync and is never written over.
- EPUBs are read under either letter case of the UUID, and pruning folds case: released Android builds wrote lowercase names. New files are written as `UUID.uuidString`.
- Everything gated by `PersistenceOperationGate` (process-wide; migration / backup import / folder sync / sweep never interleave).

## Queues / collections / library behavior

- Queue Find More links are `QueueSavedSearchLink` rows: deleting a saved search or queue removes the join, never the other endpoint. The queue's optional `searchSourcesModifiedAt` records an intentional source-list edit, including clearing the list. Backup v8 carries optional `searchSources` / `searchSourcesModifiedAt` on queues, optional `lastOpenedAt` on saved searches, and optional `lastCheckedAt` / `newResultCount` on each link. Unrecorded values omit their keys; missing keys on import retain stored values. Replace Library restores the snapshot's `searchSourcesModifiedAt`, `lastCheckedAt`, and `lastOpenedAt` when those keys are present; merge/reconcile still keep the newer stamp. Counts and `lastOpenedAt` call `FolderSyncService.markDirty()`.
- Removing a work from a queue is non-destructive; queue-only works auto-soft-delete (not hard) when leaving their last queue unsaved/unfavorited.
- Soft-deleted works keep memberships/collection links (restore re-joins) but are **filtered at render time** everywhere (`isPendingDeletion` exclusions in every list `@Query` + relationship-derived listings).
- Queue-preserved EPUBs (`epubPreservationStatus`) are protected from history-clearing paths.
- A queue, collection or pronunciation sheet whose save fails stays open, says so and keeps what was typed (iOS T-436; Android's sheets already did). On iOS the sheet rolls its `ModelContext` back, so a retry can't insert a duplicate and a later autosave can't write an edit the reader was told failed. The rollback drops every pending change in that context, but a failed save means none of them reached the store either, so what the app shows matches the disk.
- A smart queue (`ReadingQueueKind.smart`, T-533) stores its rules as one optional `smartRulesJSON` string, not a SwiftData composite. Members are computed from the local library and are never memberships. Backup v8 carries the optional key and the `kindRaw` string as written, including a kind this build does not know; a missing key on import leaves a stored value in place, including under Replace, and an archive's `kindRaw == "custom"` (an older iOS re-export, with or without `smartRulesJSON`) never downgrades an existing non-custom queue. A custom or Saved for Later queue never stores or exports `smartRulesJSON`, so no "custom + rules" hybrid can travel. Restore and sync skip stored memberships, keep-offline, and Find More `searchSources` targeting `.smart` queues, and export omits them. Do not bump `KudosBackupManifest.currentVersion`. Keep-offline does not apply. Evaluating the rules makes no AO3 request. Older shipped iOS builds decode `"smart"` as `.custom` and show an empty queue; Android filters `kindRaw == ReadingQueueKind.CUSTOM` in its UI (hiding `"smart"` queues) while preserving `kindRaw` in SQLite and re-exporting it (dropping `smartRulesJSON` until A-533).

## Migration / schema safety

- New `@Model` fields: **additive with defaults only** (lightweight migration). Follow `permanentDeletionScheduledAt` / `searchText` precedents. New types (`ReadingSession`, `ReadingFavorite`, `FandomReadWatermark`) follow the same rule on every stored property. Do not bump `KudosBackupManifest.currentVersion` past 8 for additive arrays — Android `BackupVersion.isSupported` is 1…8.
- **Composite (`Codable` struct) attributes — every stored property must be in its `CodingKeys`.** SwiftData gives each stored property of a composite (e.g. `AO3SearchFilters` inside `SavedSearch`) its own column but fills the columns through `Codable`. A stored property left out of a custom `CodingKeys` gets a column that is never written, and every later fetch fails decoding it — a crash when faulting. `5132f943` did exactly this with `fandomUnion` and broke every saved search; `SearchFiltersTests.aSavedSearchSurvivesARealSwiftDataRoundTrip` caught it the first time the suite ran on a Mac. Add the key and a lenient `decodeIfPresent`, or keep the value off the struct.
- Never name a model property `isDeleted` (CoreData collision — silently resets). Check reserved `NSManagedObject` names for any new flag.
- One-time data fixups go in `PersistenceMigrationService` stages (yield every `yieldInterval`, `modelContext != nil` guards, gate-protected, stage-aware errors). `reconcileAssets` heals hasEPUB-vs-file drift.
- Manifest changes: bump `KudosBackupManifest.currentVersion`, extend `supportedVersions`, decode-if-present with defaults, add a round-trip test.

## Known accepted risks (don't "fix" silently — they have designs pending)

- Folder sync ships all EPUB blobs both directions (full-package model); metadata+sidecar redesign is planned, own branch.
- Orphaned EPUB files (file exists, no record) are not swept.
- All list surfaces `@Query` the full table; fine to low thousands.

## Insights data snapshots and status (T-534)

- Each `ReadingSession` stores the work's categorized tags, rating, warnings, categories, creator display names, language, completion, series identity/position and publication year at the visit. Verified creator names include anonymous and orphaned bylines; without verified identities, the snapshot uses the stored comma-separated `SavedWork.author` names. Publication year uses the UTC calendar day. A one-time gated model-actor pass fills older empty rows in batches only while the work still exists; deleted works stay unknown. Snapshot fields take precedence over live work metadata in facts.
- `SavedWork.readingStatusRaw` is empty for derived status. The Insights partition uses Stopped → On Hold → Stacking → Finished → Caught Up → Reading → Saved for Later, assigning exactly one status per work. Caught Up means every posted chapter is read, irrespective of the planned total. Only an explicit action marks a work stopped. Entering Stacking records `stackBaselineChapterCount`; the update checker resumes Reading once at least `stackThreshold` chapters have been posted since that baseline, including when it is zero.
- Backup v8 adds optional keys for every field above. `metadataSnapshotRecorded` and `statusWasRecorded` distinguish recorded defaults from unrecorded rows. A recorded snapshot exports every field, including empty lists, zero, false and null; a recorded status exports every status field, including derived/empty, default threshold and cleared dates. Rows with no record export no new keys, preserving Android re-exports. Missing keys in older or Android payloads leave an existing row unchanged; do not raise the manifest version for additive fields.

## Insights D3/D4 chapter word counts and Read Aloud sessions (T-535a)

- `SavedWork.chapterWordCountsJSON` (JSON `[Int]`) and `wordUnitRaw` (`"words"` | `"characters"`) store chapter-prose-only counts measured locally via `AO3EPUBChapterWordCounter` + `AO3WordCounter` (preface, work/chapter summaries, author/chapter/end notes, afterword, and Archive plugs excluded). Language classification treats Chinese, Japanese, and Thai (plus script-dominant chapter text when language is empty) as `.characters`, kept separate from `.words` totals and pace.
- Counts are populated from the local EPUB on import (`importEPUB`, `importUserEPUB`), EPUB replacement/reconversion/update, reader preparation if empty, and a bounded gated backfill actor (`SavedWorkChapterWordCountBackfill`, never calling `SavedWork.markModified()`, preserving Folder Sync timestamps).
- `KudosBackupWork` exports optional additive `chapterWordCountsJSON` and `wordUnitRaw` in manifest v8 so freed or remote-pending works preserve chapter word counts across devices and restores; empty values omit the keys so untouched records and `CrossPlatformBackupTests` remain identical. Missing keys on import/merge preserve local values.
- `ReadingLogService.wordsRead(sessions:works:)` uses `chapterWordCounts` when total chapter words fall within 10% of `SavedWork.wordCount` (or `wordCount == 0`). When the EPUB has fewer chapters than AO3 has posted, it uses them only if some sitting's `chapterCountAtVisit` fits the counts and that prefix is within 10% of the sitting's own word count; otherwise it falls back to legacy `progress × wordCount`. A sitting with `chapterCountAtVisit == 0` infers its chapter prefix from its word count. Within a read-through a per-chapter high-water mark stops any chapter (including a revised one) counting twice; a sitting whose prefix is > 10% off its own word count gets `Δfraction × its wordCount`, and one that saw more chapters than the EPUB has is never scaled up. After a finish, the first sitting that reads forward starts a new read-through (resets the high-water) if it starts at 0, or anywhere before the finish point when the work has neither gained chapters nor grown/shrunk by more than 10% since the finish. A sitting that reads nothing in between (open at the end, scroll back) or nudges forward past a `< 1.0` finish point (end notes) does not use up that check. New chapters, or > 10% growth/shrink, continues the read-through instead. With no recorded start, a sitting right after a finish starts at 0 unless the work grew, the same rule as legacy counting.
- `ReadingLogService.setMode` splits mid-sitting mode switches (`read` ↔ `listen`) into separate `ReadingSession` rows (preserving segments shorter than `minimumPersistableDuration` from creating sub-15 s rows, and updating rate changes within `.listen` in place). Detached Read Aloud keeps the `.listen` session open on reader close until playback stops or tears down (`ReaderSpeechController` transitions + utterance activity). Visual reading pace (`ReadingInsights.wordsPerHour`, `charactersPerHour`) excludes `.listen` sittings.
- Insights scopes (owner, 2026-11-19; `HomeReadingStats.insightsScope`): the main figures count every sitting except those of works Hide Mature conceals (every adult-rated work — live or soft-deleted by its current rating, hard-deleted via a sitting's recorded `ReadingSession.rating` when one was recorded — while Hide Mature is on, whatever has been revealed; a live work re-rated General/Teen returns to main with all its sittings), so they do not change when the gate opens and nothing hidden leaks from Insights while locked (figures, names, titles, exports, exclusions, reset counts; Home's weekly stats line still counts every sitting). A Reset re-anchors any open sitting at the work's current position and finished state. Queue-only works' sittings count (time, words, fandom shares, taste, habits, finished); library-inventory figures (statuses, unread backlog, WIP freshness, stopped works, preserved stats, export status rows) use the saved library only, while exports pass `readingWorks` for sittings so queue-only exclusions, `word_unit`, D3 chapter word counts, and metadata fallbacks match the screen. The Hidden section (only those works, including deleted/soft-deleted mature works) and the combined view (Insights Options › Include Hidden) are computed only while `PrivacyGate.revealAll`; Include Hidden is view state, never stored or synced, and clears synchronously (along with hidden caches) when the gate re-locks. Exports follow the scope on screen. `InsightsOptions.filter` computes read-through boundaries and `wordsRead` history before dropping `.listen` rows so `countReadAloud = false` never alters reread classification or nil-start visual word totals.

## Insights D7 to D9 provenance data (T-536a)

Everything below is observed locally or read from a page the app already fetched. **No new AO3 request and no AO3 write** (`docs/AO3_NETWORKING_POLICY.md` is unchanged). Every field is optional or defaulted, additive on backup v8 (no version bump), and **omitted from the manifest while unrecorded**, so an untouched record re-exports exactly as before. A re-export through an older iOS build or today's Android drops the recorded keys (see the compatibility note below). A key an archive lacks never clears a local value, in any mode, including Replace Library; a sitting that has no D7 timing yet is **filled** (never overwritten) from a matching archived sitting in Merge and Reconcile too.

- **D7 time on each chapter** (`ReadingSession`): `chapterSecondsJSON` (`{"<spineIndex>": seconds}`, active seconds credited to the chapter the reader was in *before* each move), `chapterWordsJSON` (words of the chapters the sitting read whole: entered from the one before and left for the one after, counted in words), `skimmedChaptersJSON` (`[Int]`, `"[]"` = judged, none), `endedAtChapterEnd` (saved position at or past 95% of its chapter), `peekedAtEnding` (jumped to the last chapter, of three or more, from before the halfway mark). Gathered in memory in `ReadingLogService.OpenSession` from `noteActivity(for:chapter:)` (called from the Readium `onLocatorChange`) and written only with the sitting, never from the debounced locator path. The first report only establishes where the reader is; the macOS reader reports none, so its rows keep nil. **Skim judgement** (`ChapterTiming`): a chapter of 300 words or more read whole in under half the time the median pace needs, judged once when the row is saved from the *other* read-mode sittings' whole chapters, only after 20 such chapters exist, only for a `.read` sitting of a work counted in words (characters and listening are never judged), and then stored: a later change of pace never re-judges a past sitting. Skimmed chapters do not feed the pace. Restore keeps only well-formed, in-range JSON (seconds 0 to a week, words 0 to 10 million, spine indexes 0 to 100,000, duplicates collapsed), so no imported number can overflow a figure. A saved judgement is **frozen per chapter**: a later save of the same sitting (pause, resume, close) judges only chapters not judged before, so a pace that moved in between never rewrites it. `ReadingLogService.wordsRead` deducts the words of stored-skimmed chapters from that sitting; on the chapter path (`skimmedStoryChaptersJSON`, by AO3 story chapter) a skimmed chapter is left uncredited and does not advance the chapter high-water mark, so a later full read of it in the same read-through earns its words; only a work without usable chapter counts deducts after the fact.
- **D8 where a work came from** (`SavedWork.importSourceRaw`, `importSourceSince`): set once when the work is created, never replaced by a re-import, refresh or restore (a recorded path wins; Replace Library adopts the archive's). A path that does not know records `unknown`, so "since" still marks when recording began; works saved before recording stay nil. **The source is the tapped row's page**: Search, fandom, author and tag rows carry their origin in the Work Detail route (`RemoteWorkRoute`), so a detail-page save records that page, never Unknown. **One fact with T-528's queue origin**: `WorkImportSource(origin:)` maps a membership origin (search/source to `search`, link to `pastedLink`, manual to nothing) and a queue add passes it as the source when the add creates the work. `backupRestore` exists in the vocabulary but nothing writes it: restore carries the archive's own value or leaves nil, since claiming "restored" would overwrite the true origin with a guess.
- **D9 kudos and hits when saved** (`kudosAtSave`, `hitsAtSave`, `bookmarksAtSave`, `statsSavedAt`, `ageDaysAtSave`, `fandomWorksAtSave`): one group, written once by `recordStatsAtSave`: at creation from the blurb the work was made from, or by the first metadata fetch **while the work is within `saveStatsWindow` (15 min) of `dateAdded`, for a work this build created (it recorded `importSourceRaw`)** (an import carries no kudos, so the refresh right after it is the first sight; a later refresh returns false and leaves the group alone). Metadata refresh keeps updating `kudos`/`hits` and never touches these. The age is measured in GMT days from the posting date to `statsSavedAt`, and `completeAgeAtSave` fills it when the work page later brings the date. `fandomWorksAtSave` is filled only when the save came from a fandom page that had already loaded that fandom's total (one fandom, no list filters at the moment of the save, the work is in that fandom; a filter change clears the total, the `.fandom` source stays; `ReadingQueueMembershipOrigin.fandomWorks`, never stored on the membership); Kudos persists no fandom size. Merge: set once, a local group stays; Replace Library adopts the archive's snapshot **member by member**: an omitted member (age, fandom size) never clears what is here. The age is counted to `dateAdded`, so a window crossing midnight adds no day.
- **Hide Mature applies to every figure** (`Services/InsightsProvenance.swift`): the figure functions take only rows that went through `InsightsScopeSelection` (`libraryWorks` / `readingWorks` for D8 and D9, `sessions(_:in:)` for D7), so a concealed work's source, stats or sitting never reaches a figure while locked and lands in Hidden or the combined view only while revealed.

### Cross-version compatibility of the T-536a keys

The importer **never clears a recorded D7 to D9 value when an archive omits it, in any mode** (Reconcile, Merge, Replace Library); that is tested. What we cannot control: an **older iOS build** decodes the manifest into typed structs (`KudosBackupWork`, `KudosBackupReadingSession`, `KudosBackupManifest`) that have no property for the new keys, so importing a T-536 archive and re-exporting it drops them. **Android** ignores unknown keys and writes its own typed manifest, so it does the same until **A-541** adds an Android passthrough (shipped clients cannot be fixed from here). **Plainly: an archive that has passed through an older iOS build or today's Android loses the D7 to D9 keys, and a fresh store restored from that re-export cannot get them back; the original current-client archive is the only authoritative copy, and the importer cannot reconstruct stripped data.** This is the same class of loss as the other additive v8 keys. No place that older builds preserve unknown data exists for these keys, and none was invented. Within current builds the keys round-trip through backup and Folder Sync.
