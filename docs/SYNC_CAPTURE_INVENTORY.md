## 0. How to read the rows

**Columns.** `file:line` is the write itself (the assignment, insert, delete or DAO call), not the function header. *Entity . groups* uses D4 names (SavedWork value groups: Identity, Lifecycle, Text metadata, Counters, Flags, Monotonic, Reading status, Progress, Tag lists, User tags, Preservation, Cover pin, Insights provenance, Chapter word counts, Asset facts, Authors, Download date, Derived/device, Record clock). *Owner . commit* is the context or transaction that holds the write and how it reaches disk. *Origin . freq* is where the write comes from and how often. *Capture* is the strategy recommended for that row; *blocker* is what stops it from being safe today.

**iOS context owners.**
- **MC** = the one shared main-actor `ModelContext` that `.modelContainer(Self.sharedModelContainer)` injects (`App/MyApp.swift:25,50`). Autosave is ON. Every view's `@Environment(\.modelContext)`, every `@Query`-bound edit, every `static func ...(in context:)` service and the sync observer write here, so one dirty change from any writer is committed by the next unrelated `save()`.
- **BG** = a second context, `ModelContext(container)` (`Services/FolderSyncBackgroundTask.swift:65`), used by the BGAppRefresh task.
- **ACT** = `@ModelActor` private contexts (`Services/PersistenceSync.swift:769,804`), `modelContainer`-scoped, off the main actor.
- **RESTORE** = `KudosBackupService.restore` runs on the caller's MC but flushes it first (`Services/KudosBackup.swift:3205-3207`), turns autosave off for the call (`:3212-3214`) and commits once at `:4715`, with `rollback()` on throw (`:3232`).

**iOS commit paths.**
- **SBE** = `saveBestEffort(reason:)` (`Utilities/ModelContext+SaveBestEffort.swift:48`): returns true WITHOUT saving when `autosaveEnabled == false`, logs a failure, never throws.
- **COMMIT** = `commitNow` (`:59`): saves even with autosave off (used by Sort New Undo, `Services/QueueSortNew.swift:654,738`).
- **SAVE?** = `try? context.save()`: failure swallowed. **SAVE!** = `try context.save()`: throws to the caller.
- **AUTO** = no explicit save at all: the change waits for SwiftData autosave or for another writer's `save()`.
- **rollback** = the writer calls `context.rollback()` on the shared MC on failure (also discards other writers' unsaved edits): `Features/Library/Collections.swift:294`, `Features/Home/HomeView.swift:1196`, `Features/Library/NewCollectionSheet.swift:175`, `Features/Library/ReadingQueueOrganizer.swift:636`, `Features/Library/ReadingQueueBrowser.swift:1686`, `Features/Library/NewReadingQueueSheet.swift:904`, `Features/Library/ReadingInsightsSheets.swift:484`, `UIComponents/RemoteWorkSelection.swift:411`, `Services/QueueSortNew.swift:655,739`.

**Origins.** `U` user command (tap, swipe, sheet); `R` reader checkpoint; `IM` import/download; `RS` restore or folder-sync apply; `MG` migration/backfill; `SW` sweep/background task; `AO` AO3 refresh (a network read that rewrites local fields); `LCH` launch task.
**Frequency.** `1` per command; `PT` per page turn / scroll settle but throttled; `O` per reader open/close; `L` per launch; `B` bulk (N rows in one pass); `K` per keystroke.

**Capture codes (iOS).** `CMD` = command-owned save on an isolated, autosave-disabled context plus outbox rows in the same save (plan § B). `CMD-after-draft` = same, but the writer must first stop editing live `@Query` objects (use a draft or a command). `SNAP` = leave to snapshot reconciliation (derived, device-local, or no recoverable intent). `NONE` = must not be captured (derived / device-local / transport state).
**Capture codes (Android).** `TRG` = SQLite trigger on the table. `DAO` = an explicit DAO operation that writes the outbox row in the same `withTransaction`. `TRG+DAO` = trigger for the row diff, DAO op for intent / origin. `SNAP` / `NONE` as above.

**Hazard tags used in the blocker column.**
- `H-shared` writer shares the dirty MC with unrelated writers (the outbox row and the change could be committed by different saves, or one writer's `rollback()` discards another's change).
- `H-auto` change relies on autosave or on a later unrelated save.
- `H-swallow` `try?` save: a failed save leaves dirty state that a later save commits without the command that made it.
- `H-nostamp` the write changes synced data but does not call `markModified` / bump the record clock, so the folder-sync change token (`App/FolderSyncObserver.swift:118-134`, `lastModifiedAt`/`dateAdded`/`dateUpdated` newest per entity, whole-second floor) and any `lastModifiedAt`-keyed diff will not see it.
- `H-cascade` SwiftData relationship delete rule or SQLite FK `ON DELETE CASCADE` removes related rows with no command intent.
- `H-relationship` a to-many relationship (`SavedWork.collections`, `SavedWork.tags`, `ReadingQueue.tags`) changes with no row of its own to carry a stamp or tombstone.
- `H-bulk` one pass touches every row or a bounded batch; per-row outbox rows would be a bulk write.
- `H-order` the file write and the database write are not atomic with each other.
- `H-replace` (Android) `OnConflictStrategy.REPLACE` = delete-then-insert; SQLite does not fire `DELETE` triggers for a REPLACE conflict unless `recursive_triggers` is on, and FK children of the deleted row cascade.
- `H-wholerow` (Android) read-modify-write of the whole row through `workDao.upsert(work.copy(...))`: a stale read writes back untouched columns; a trigger cannot tell which value group the command meant.

## 2. Android (Room) writers

Android paths are under `android/app/src/main/java/io/github/cidy02/kudos/` (omitted below). Room database `KudosDatabase` version 15, 16 entities (`data/local/KudosDatabase.kt:33-50`); no `SavedSeries`, `FollowedTag` or `TagAlias` tables. This branch carries unknown incoming manifest fields only in the sync JSON merge (A-I03); it has no persisted opaque overlay. Every DAO write goes through `RoomDatabase` (single writer connection; `database.withTransaction` is the only multi-statement atomic scope).

**Android owners and commit paths.**
- **DAO1** = one DAO call outside a transaction (Room wraps each `@Insert`/`@Upsert`/`@Update`/`@Query(UPDATE|DELETE)` in its own implicit transaction; two DAO calls in a row are two commits).
- **TXN** = inside `database.withTransaction { ... }`. `@Transaction` DAO method = `TXN` as well (`data/local/dao/AnnotationDao.kt:35`).
- **UPSERT** = `@Upsert` (insert, or in-place UPDATE on a key conflict; no delete, no cascade, `data/local/dao/WorkDao.kt:12-17`). **REPLACE** = `@Insert(onConflict = REPLACE)` (delete + insert; cascades and trigger semantics per `H-replace`): `BookmarkDao.kt:11`, `CollectionDao.kt:24` (cross-ref), `CustomFontDao.kt:12`, `SavedSearchDao.kt:11`, `TagDao.kt:12,15`.
- **GATE** = also behind `persistenceGate` (`backup/BackupRepository.kt:89,524-529`, `KudosApplication.kt:72`), the process-wide mutex that serialises import / sync / sweep. Ordinary UI writes do NOT take it (`backup/BackupRepository.kt:776-777`, `:877-880` say so).
- **Existing change signal.** `backup/DatabaseChangeTracker.kt:15-35` observes `works`, `reading_queues`, `reading_queue_memberships`, `annotations`, `reading_sessions`, `collections`, `collection_work_cross_refs`, `sync_tombstones` through Room's `InvalidationTracker` and only sets "has pending changes". Not observed: `user_tags`, `work_tag_cross_refs`, `queue_tag_cross_refs`, `bookmarks`, `saved_searches`, `custom_fonts`, `reading_favorites`, `fandom_read_watermarks`. Room's invalidation uses its own `room_table_modification_log` triggers (created when an observer registers); capture triggers would live beside them.

## 5. Highest-risk paths for G-capture

1. **The shared main `ModelContext` (iOS, every row marked MC).** One autosave-ON context is written by views, services, the detached read-aloud saver (I-A06), restore (I-G01) and, via a second context, the BG task (I-G21). An outbox row staged by one command can be committed by another writer's `save()`, and seven writers call `rollback()` on it (listed in § 0). `saveBestEffort` is not a boundary: it returns true without saving when autosave is off (`ModelContext+SaveBestEffort.swift:48-51`). Sort New Undo (I-D08) is the only writer that checks the context is clean first.
2. **Restore / sync apply (I-G*, A-G*).** Bulk, changed-or-not writes with no origin tag; iOS commits once on the shared MC after a pre-flush that commits other writers' dirty state (`KudosBackup.swift:3205-3207`); Android upserts every row of the snapshot in one transaction (A-G01), so a per-row trigger fires for unchanged rows. Settings, pronunciations and recovery files are applied outside the model/Room commit (I-G18..20, A-G12/13); the current Android base has no persisted opaque overlay (A-I03).
3. **Reader progress (I-A02, A-A02).** Highest frequency, a deliberate non-stamp on iOS (`lastModifiedAt` untouched, so every `lastModifiedAt` diff misses it), and a whole-row read-modify-write on Android with a documented lost-update race.
4. **Relationship cascades and implicit memberships.** iOS: `SavedWork.collections`, `SavedWork.tags`, `ReadingQueue.tags` have no row; work hard-delete nullifies collection links with no tombstone (I-B23, I-C07). Android: FK `ON DELETE CASCADE` removes tag and collection cross-refs on work delete (A-B10); REPLACE remains hazardous at A-B11, A-G04 and A-E01/03/04. The guarded user add A-C02 does not replace an existing pair.
5. **Writers that change synced data without a clock bump (`H-nostamp`):** I-A07, I-B15 (tag rename), I-B17 (cover pin), I-B19, I-B24, I-D09, I-F04 (progress reset without `progressModifiedAt`); Android user tags (A-B11) and `restoreHeldCopy`-style device-local writes that DO bump it (A-B04/05).
6. **Non-atomic multi-statement commands on Android:** `softDelete` and restore (A-B08/09), `addWork` (A-D04), collection soft/hard delete (A-C04), saved-search delete (A-E02), user tags (A-B11).
7. **Launch/bulk passes that would flood the outbox:** `normalizeAllQueuedWorks` (I-D14), `migrateMetadata` (I-H01), cover backfills (I-H04), Android `repairMissingEpubFlags` and the `lastModifiedAt`-stamping device-local writers.

## Integration notes

This inventory is based on the **v3.3 plan already present in this worktree**. Its dependency-validity check (coverage does not prove a prerequisite's kind/owner), checkpoint state and atomic cut, fenced retirement, per-lineage expiry bases, signed authority heads, observed-epoch records, and D7 byte/retained-object budget remain plan requirements. No v3.3 text was changed here. A capture implementation must retain those facts, pending dependencies, outbox rows and receiver cursors when switching store generations; neither a snapshot diff nor a journal coverage vector substitutes for them.

Plan edits still needed from D6 before G-capture is executable:

- Specify the **source-side pending-intent to database-outbox bridge** for UserDefaults, DataStore and atomic files, including a single-record or write-ahead protocol for nontransactional UserDefaults, acknowledgment order, ambiguous intent handling, remote-apply origin, and kill/restart tests (I-I01..I-I04, I-I08, A-I01..A-I06, A-I08). The present § B requirement for a reconciliation contract does not give this commit protocol.
- Resolve `ao3Unavailable`'s false transition in D4 and then align the plan's capture gate with it (I-B25, I-F09/10, A-F03/04/07). Current D4 grow-only OR cannot represent both directions.
- Add a D4 operation or reviewed deterministic exclusion for an existing session's metadata-snapshot backfill (I-H06), then state the choice in the plan's D6 capture gate. Cover pins and chapter data already have D4 value groups and require captured facts unless similarly excluded with proof (I-H04/07/13).
- Spell out that logical W8/W9/FN1/FN2/O1 references are captured separately from local file presence, and that generation activation preserves/rebases unsent outbox rows and receiver cursors (I-I05..I-I07, A-I04, § 6). The v3.3 plan states both principles; D6 needs explicit acceptance tests for these writer paths.
