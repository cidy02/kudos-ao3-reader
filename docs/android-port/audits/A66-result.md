# A66: Settings, Backup, Sync, Privacy, Onboarding, Support and Sign-in Action Audit (iOS vs Android)

**Audited:** 2026-10-20
**iOS source:** `/Users/cidy02/kudos-ios-polish/kudos-ao3-reader/`
**Android source:** `/Users/cidy02/kudos-agent-gemini2/android/app/src/main/java/io/github/cidy02/kudos/`

## Priority List (Most Harmful First)

1. **`Privacy & Local Data` — Bulk `Free up space`, `Clear reading positions`, `Clear reading history`, and `Clear browse cache` wipe data without confirmation when `Confirm before deleting` is off (`Features/Account/PrivacyDataView.swift:120-177, 381` vs `settings/PrivacyDataScreen.kt:39, 170-185`, `ui/components/DestructiveConfirmation.kt:23-28`):** On iOS, all four bulk-clear actions unconditionally present a `.confirmationDialog(...)` regardless of `confirmBeforeDelete` (which `Settings › Library` defines as `"asks before a swipe removes a work from your Library"`), matching the section's own promise: *"Each option asks before it clears anything and tells you what will change on this device."* On Android, `PrivacyDataScreen` passes `confirmBeforeDelete = settings.app.confirmBeforeDelete` into `DestructiveConfirmation`, so if the reader turned off swipe-delete confirmation in `Settings › Library`, tapping any of the four rows immediately deletes finished EPUB files, wipes reading positions across the entire library, soft-deletes reading history, or clears the browse cache with zero confirmation.
2. **`MatureContent` Privacy Gate — `Hide mature content` / `Obscure` ignores `Not Rated` works with adult archive warnings (`Features/Privacy/MatureContent.swift:31-101` vs `library/LibraryPrivacy.kt:60-66`, `library/LibraryQuery.kt:201-207`, `settings/AvailabilitySweepScreen.kt:47-51`):** On iOS, `MatureContent.isMature(rating:archiveWarnings:)` treats works rated `"Not Rated"` or `""` as mature when their `archiveWarnings` contain any of `"Graphic Depictions Of Violence"`, `"Major Character Death"`, `"Rape/Non-Con"`, `"Underage"`, or `"Underage Sex"`. On Android, `SavedWork.isAdultRated()` checks only whether `rating` contains `"mature"` or `"explicit"`, leaving `Not Rated` works tagged with `Rape/Non-Con` or `Underage Sex` completely visible when `Hide mature content` is on.
3. **`Settings › Backup` (`Import Backup…`) — `Replace Library…` is hidden when the library has 0 works even if it has saved links, saved searches, collections, or custom reading queues (`Settings/SettingsBackupPage.swift:64-80`, `Settings/BackupImportSheet.swift:56, 94-103` vs `backup/KudosBackup.kt:76`, `backup/BackupScreen.kt:449-478`):** iOS offers `Replace Library…` whenever `hasAnythingReplaceWouldRemove` is true (`works.contains { !$0.isPendingDeletion } || !bookmarks.isEmpty || !savedSearches.isEmpty || !collections.isEmpty || readingQueues.contains { $0.kind != .savedForLater }`), because Merge is add-only and cannot prune those records. Android checks only `preview.isLibraryEmpty` (`localWorkCount == 0`), so a library with 0 works that still holds bookmarks, saved searches, collections, or custom queues is offered only `"Restore from Backup"` (`MERGE`) and has no way to make the device match the backup.
4. **`Settings › Font` — `Add Font…` accepts fonts that break library backup export and Replace Library (`Settings/SettingsView.swift:245-260, 277-290` vs `settings/SettingsPages2.kt:524-674`, `files/CustomFontRepository.kt:36-76`):** iOS rejects any font over 4 MB, any font with invalid TrueType/OpenType magic bytes (`KudosBackupContents.fontRejectionReason`), or any addition pushing total installed fonts over 32 MB (`fontTotalRejectionReason`) before saving. Android checks only non-empty bytes and `.ttf`/`.otf` extension on import, so importing a >4 MB font (e.g., a CJK font), >32 MB total, or a non-SFNT `.ttf` succeeds in `Settings › Font` and then causes `BackupExporter.exportV2` (`backup/BackupExporter.kt:65-69`) and pre-Replace safety backups to fail with `EntryTooLarge` or `InvalidPackage`.
5. **`Settings › Import` & External File Open — Picking or sharing a `.kudosbackup` archive routes it through EPUB work import instead of `BackupImportSheet`, and picker MIME filter omits `.zip` / `.docx` / `.md` / `.rtf` / `.odt` (`Settings/SettingsImportPage.swift:26-29, 92-99, 134-162` vs `settings/SettingsPages2.kt:94-100, 141-157`, `app/KudosApp.kt:60-85, 179-219`):** On iOS, `Settings › Import` accepts `.kudosBackup` and `.folder` alongside document types and routes backup archives to `BackupImportSheet`. On Android, `Settings › Import` and `ExternalFileImport` pass all picked/shared URIs into `prepareDocumentImports` → `DownloadDateImportConfirmation` → `WorkImporter.importLocalEpub`, so selecting a `.kudosbackup` prompts for a work download date and then fails work import. In addition, `EpubOpenMimeTypes` (`SettingsPages2.kt:94-100`) only passes `application/epub+zip`, `application/pdf`, `text/html`, `text/plain`, and `application/octet-stream`, even though the page footnote promises `"zipped chapters"` (`application/zip`) and `WorkImporter` supports `.docx`, `.md`, `.rtf`, and `.odt`.
6. **`Settings › Appearance` — `Text Size` slider and spacing/margin sliders unconditionally force `readerCustomize = true` (`publisherStyles = false`) with no toggle to turn `Customize` off (`Features/Reader/TextSizeSlider.swift:7-29`, `Features/Reader/CustomizeThemeView.swift:78-104` vs `settings/SettingsPages.kt:121-191`):** On iOS, changing `Text Size` only writes `readerFontPt` and leaves `readerCustomize` untouched, and `CustomizeThemeView` provides a master `Customize` toggle plus `Reset Theme`. On Android, adjusting `Text Size` (`SettingsPages.kt:126`) or any spacing/margin slider (`SettingsPages.kt:145, 159, 173, 187`) forces `readerCustomize = true` (`publisherStyles = false`), and `Settings › Appearance` has neither a `Customize` toggle to turn custom layout off nor a `Reset Theme` button (queued in brief `3fs`, not yet landed).
7. **`Settings › Appearance` — `Customize Theme…` toggles the accent-color hex editor instead of opening the reading-text customization sheet (`Settings/SettingsReadingPages.swift:44-48, 61-67`, `Features/Reader/CustomizeThemeView.swift:11-270` vs `settings/SettingsPages.kt:109-119`):** On iOS, `Customize Theme…` opens a sheet with a live prose preview, 4 reader theme swatches, `Font` picker, `Bold Text` toggle, master `Customize` toggle, 4 layout sliders, `Justify Text` toggle, and `Reset Theme`. On Android, `Customize Theme…` toggles `showCustomize` (the same inline `AccentCustomizeBlock` as tapping `Accent Color` on line 99), while the 4 sliders sit inline below without live preview, `Customize` toggle, or `Reset Theme` (queued in brief `3fs`, not yet landed).
8. **`Settings › Backup` — Double-hop `SettingsBackupPageWrapper` requires tapping `Export Backup…` or `Import Backup…` twice (`Settings/SettingsBackupPage.swift:82-136` vs `settings/SettingsPages2.kt:405-457`, `backup/BackupScreen.kt:60-280`):** On iOS, `Settings › Backup` directly opens the file exporter/importer when `Export Backup…` or `Import Backup…` is tapped. On Android, `Settings › Backup` opens `SettingsBackupPageWrapper`, where both `Export Backup…` and `Import Backup…` merely call `onOpenBackup` (`navController.navigate(Routes.Backup)`), opening a second `Backup` screen (`BackupScreen.kt`) where the reader must tap `Export Backup…` or `Import Backup…` a second time. `SettingsBackupPageWrapper` also adds an Android-only `"Reset settings to defaults"` action (`SettingsPages2.kt:437-456`).
9. **`Settings › Backup` (`Replace Library`) — Pre-Replace safety copy is written after confirmation instead of on sheet appearance, without 3-attempt retry, and `"far fewer works"` threshold differs (`Settings/SettingsBackupPage.swift:394-442`, `Settings/SettingsView.swift:398, 405-437, 487-504` vs `backup/BackupScreen.kt:142-159, 375-384`, `backup/KudosBackup.kt:77-78`):** On iOS, opening the `Replace Library` confirmation step immediately saves the safety copy (retrying up to 3 times) and shows its filename (`"A copy of your current library was saved as <name>."`) or blocks the `Replace Library` button before the reader can tap it. On Android, the safety copy is only written once after the reader taps `Replace Library`. Also, iOS warns `"This backup has far fewer works than your current library."` only on the Replace step when `willRemove >= 20 && willRemove >= willAdd * 10`; Android warns on both the initial choice step and Replace step whenever `willRemove > 0 && fileWorkCount * 2 < localWorkCount`.
10. **`Deletion signing` (`Sync Folder` / `Backup`) — Tapping `"N deletion(s) skipped from an unpaired device"` does not clear the counter, and `Revoke` (`Stolen or compromised`) auto-restores works from Recently Deleted on Android only (`Settings/PairingSheet.swift:79-92, 143-151` vs `backup/PairingSheet.kt:127-134, 208-224`, `backup/KeyRevocationService.kt:37-46`):** On iOS, tapping the skipped-deletions warning calls `UnknownSignerTracker.reset()` so the prompt is dismissed once acted on; on Android, tapping it opens `PairingBottomSheet` without clearing `unknownSignerTombstoneIds`, leaving the warning row visible indefinitely if the reader chooses not to pair that device. Conversely, when revoking a device as `Stolen or compromised`, Android automatically restores works in Recently Deleted signed by that key (`restoreWorksDeletedBy`) while iOS only revokes/denylists the key.
11. **`Sign-in` (`AO3NativeLoginScreen`) — Native login does not check AO3's `#user_remember_me` checkbox, so AO3 never issues the `user_credentials` remember-me cookie (`Services/AO3WebLoginCoordinator.swift:324-328`, `Services/AO3AuthService.swift:278-287` vs `auth/AO3NativeLoginScreen.kt:272-288`):** On iOS, `AO3WebLoginCoordinator.submit` checks `#user_remember_me` (`if (remember) remember.checked = true`) so AO3 sets the long-lived `user_credentials` cookie alongside `_otwarchive_session`. On Android, `AO3NativeLoginScreen`'s form-fill script sets only `user[login]` and `user[password]`, so native logins omit `user_credentials` and the session expires as soon as `_otwarchive_session` expires.
12. **`Sign-in` (`AO3NativeLoginScreen`) — Failed login clears the password field, replaces AO3's flash error with a generic message, does not auto-fallback when the login form is missing, and omits keyboard `Go` submit (`Features/Auth/AO3LoginView.swift:120-125, 206-212`, `Services/AO3WebLoginCoordinator.swift:198-215, 361-368` vs `auth/AO3NativeLoginScreen.kt:262, 293-299, 325-329, 398-408`):** On iOS, a failed login keeps `password` in the field so fixing a typo does not require retyping, scrapes AO3's `#main .flash.error, .flash.alert` text, automatically switches to the visible WebView fallback if the form is missing or altered, and submits when the user presses `Go` on the password keyboard. On Android, every failure branch sets `password = ""`, shows `"Login failed. Check your username and password."`, stays on the native screen when the form is missing (`"Couldn't find AO3's login form. Try the alternative method."`), and sets no `ImeAction.Go` / `KeyboardActions` on the password field.
13. **`Settings › Sync Folder` — Missing `Metadata` status row and `Check Metadata` / `Retry Metadata Prep` action, and sync/connect errors do not present a modal alert (`Settings/SettingsSyncFolderPage.swift:58-107, 134-138, 187-201` vs `settings/SettingsPages2.kt:677-797`):** iOS shows `Metadata` (`Ready` / `Needs Retry`), `Last Checked`, and a `Check Metadata` / `Retry Metadata Prep` button, and presents an alert when connecting or syncing fails. Android shows only the inline error footnote at the bottom of the page and has no `Metadata` check row.
14. **`Settings › Listening` — Missing `Pronunciations` screen and actions (`Features/ReaderReadium/ReaderSpeechSettingsSection.swift:138-145`, `Features/ReaderReadium/ReaderPronunciationSettingsView.swift:16-436` vs `settings/SettingsListeningPage.kt:164-204`):** iOS offers `Pronunciations` (add/edit/delete word → IPA/respelling overrides, live phoneme preview, dismiss guessed words, `Paste Corrections` from clipboard, `Copy All` to clipboard, and `Scan this chapter` when opened from the reader), and includes `pronunciations` in backup export/restore (`Services/KudosBackup.swift:3464`). Android has no pronunciation UI or backup export/restore (queued in brief `3ft`, not yet landed).
15. **`Settings › Listening` — Missing Kokoro Voice Pack download, cancel, and retry actions (`Features/ReaderReadium/ReaderSpeechSettingsSection.swift:225-417` vs `settings/SettingsListeningPage.kt:151-162`):** iOS lets the reader download, cancel, or retry the Kokoro voice pack directly in `Settings › Listening` (with a privacy disclosure confirmation dialog). Android shows only a non-interactive status row (`Voice Pack Downloaded` / `Not downloaded`) and tells the reader to open a work in the reader to download it.
16. **`Settings › Listening` — Missing `Engine` picker, `Pitch` slider, and `Developer Settings` (`Features/ReaderReadium/ReaderSpeechSettingsSection.swift:68-73, 147-154, 169-180`, `Features/ReaderReadium/ReaderSpeechDeveloperSettingsView.swift:19-170` vs `settings/SettingsListeningPage.kt:164-204`):** iOS offers an `Engine` picker (`Automatic` / `Kokoro` / `Apple`), a `Pitch` slider (`0.5×–1.5×`, reset by `Reset Read Aloud`), and `Developer Settings` (5 pause sliders, 3 chunk-size sliders, 2 boundary toggles, `Reset to shipped defaults`). Android has none of these on `Settings › Listening`.
17. **`Settings › Reader` — Missing `Two-page spread` toggle on tablets/wide screens (`Settings/SettingsView.swift:108-114, 126-129` vs `settings/SettingsPages.kt:197-250`):** iOS shows `Two-page spread` (`readerTwoPage`) on non-phone devices (disabled when layout is not `Paged`). Android maps `reader.readerTwoPage` in `ReaderSettingsMapper.kt:33` and backs it up, but offers no toggle for it in `Settings › Reader`.
18. **`Settings › Reader` — Toggling `Justified text` does not enable `readerCustomize`, unlike `Bold text` (`settings/SettingsPages.kt:213-236`, `reader/settings/ReaderSettingsMapper.kt:39-42`):** On Android, `Bold text` sets `updateReaderCustomize(true)` (`SettingsPages.kt:221`), whereas `Justified text` only calls `updateReaderJustify(it)` (`SettingsPages.kt:233`).
19. **`Settings › Downloads` — `Storage used` total measures `context.filesDir` recursively instead of `LocalDataFootprintScanner.measure()` (`Settings/StorageUsedRow.swift:14-36` vs `settings/SettingsPages.kt:256-262, 298`):** iOS computes `Storage used` in `Settings › Downloads` via `LocalDataFootprintScanner.measure()` (`footprint.totalBytes`) specifically so `Settings › Downloads` and `Privacy & Local Data` never show conflicting totals. Android's `SettingsDownloadsPage` sums `context.filesDir` using logical `file.length()` (`SettingsPages.kt:259`), which differs from `LocalDataFootprintScanner.measure()` (`settings/LocalDataFootprint.kt:64-83`).
20. **`Settings › Reading Queues › Queue Storage` — Missing swipe-to-`Keep Download` action and clickable author bylines (`Features/Library/ReadingQueues.swift:308-324, 382-390` vs `settings/QueueStorageScreen.kt:185-215, 241-243, 258-268`):** On iOS, works with `!work.isSaved` offer `Keep Download` on **both** trailing swipe and long-press context menu, and verified author names in the row byline link to native author profiles (`AO3AuthorBylineView`). On Android, swipe only triggers `Remove from Queues` (`Keep Download` is only in the long-press menu), and the author byline is plain non-clickable text.
21. **`Settings › AO3 Account` — Missing `auth.noticeMessage` display in section footer (`Settings/SettingsAccountPages.swift:156-158` vs `settings/SettingsPages2.kt:207-210`):** When `AO3AuthManager.noticeMessage` is populated (e.g., session expiration or notice), iOS renders it as the section footer on `Settings › AO3 Account`; Android always renders the static sign-in footnote.
22. **`Settings Hub` — `Downloads` row value ignores `Download on subscribe` (`Settings/SettingsRoute.swift:100, 117-119` vs `settings/SettingsHubScreen.kt:66-67`):** When `Keep works you read` is off and `Download on subscribe` is on, iOS shows `"On subscribe"` on the hub's `Downloads` row; Android checks only `keepsWorksYouRead` and shows `"Manual"`.
23. **`Privacy & Local Data` — Missing pull-to-refresh on storage footprint (`Features/Account/PrivacyDataView.swift:119, 396-399` vs `settings/PrivacyDataScreen.kt:35-218`):** iOS provides `.refreshable { await measure() }` to re-scan `LocalDataFootprintScanner.measure()`; Android only measures on initial composition and after `Free up space` / `Clear browse cache`.
