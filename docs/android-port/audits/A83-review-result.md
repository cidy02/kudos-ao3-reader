### iOS 921a07f1 (T-430, T-431)
- **P2. WritingTextEditor.swift `WritingRecoveryCopyText` (≈L558): the recovery copy can no longer be copied out whole.** It used to be one `Text(recovery.text).textSelection(.enabled)`: on iOS a long-press copies the whole string, and on macOS you can drag-select all of it. Now it's one `Text` per line in a LazyVStack. `.textSelection` applies per `Text` and doesn't select across views, so the user can copy one paragraph at a time and off-screen lines aren't even built. The sheet has no Copy or Share button. Its only exits are Restore (overwrites the form), Keep form text, and Delete (destructive). So "keep the form, but save my recovered text somewhere" goes from one long-press to N. Scenario: a 510k-char recovery copy and the user wants it in Notes without replacing the form. Verified by reading. The platform behaviour is standard SwiftUI (not run). Android's lazy list of lines has the same limit, so the fix belongs in both apps: a Copy button that puts `recovery.text` on the pasteboard, or ShareLink.
- **P3. CommentsModel.swift ≈L455-486 (Inbox "Chapter Comments" focus path): a kept copy is presented without the notice.** `fetchPage(1, …)` can return the kept page after a failed read; that sets `isFromCache=true, isKeptAfterFailure=true` (L882-885). L484-486 then clears both unconditionally before `phase = .loaded`. Scenario: the focused comment page loads, the chapter's page 1 read times out, and a cached page 1 exists → the merged page shows with no "AO3 couldn't be reached / You're offline" line. The same path also hid the old offline banner, so it predates this commit, but T-430's goal misses it. Verified by reading.
- T-431 lazy Preview: AO3RichTextView `isLazy` only switches VStack/LazyVStack and is used only inside WritingRenderedPreview's ScrollView. No finding. Nit: the new structs were inserted between `WritingBufferPreview`'s doc comment ("OD1's preview model…") and the enum, so that comment now documents `WritingRenderedPreview`.
- keptCopyNotice itself: every success, fresh-cache and reset path clears `isKeptAfterFailure`; auth-required and cold-miss failures end in `.failed`, which draws no banner. Sound apart from the P3 above.

### iOS 776cebcd + 7dc23568 (T-432 DEBUG shot routes)
**Release / leak: no finding (verified mechanically).** DemoLibrary.swift is `#if DEBUG` from L1 to L830 (DebugShots, DebugLaunchRoute, DemoNetworkBlock including the new `isPreview` and `/series/<id>/manage`). Every line both commits changed outside DEBUG is one of: two `// swiftlint:disable:this type_body_length` comments, a `// swiftlint:disable file_length`, and one moved closing brace (EditMultipleWorksView.swift:68; braces balance in both configurations). macOS Release isn't built by the commit, but nothing reaches it, and the DEBUG-only code compiled for macOS Debug per the commit.
**No shot pending: no finding.** Every hook is `takeSheet` / `takePush` / `wantsPush` against `shot?.…`, which is nil without a `shot:` launch value. `pageRoute` = `shot?.route ?? value`, so non-shot launches are unchanged. `preview_button` only matters inside DemoNetworkBlock (the demo network).
- **P3, DEBUG. ReadiumReaderView.swift `applyDebugShot` ("readernote"): each run inserts another highlight into the persistent store.** It calls `modelContext.insert(ReadingAnnotation(…))` with a made-up locator (`/chapter.xhtml`) and text, with no lookup first. DemoLibrary.seedIfRequested returns early on an installed demo and never removes annotations. So every readernote launch (4 themes × AX5…) adds a duplicate on Sodium Lights, and later reader and Contents shots inherit them. Android dedupes through `findSamePassage`. Verified by reading.
- **P3, DEBUG. PairingSheet.swift / DemoLibrary.swift `revokedDevice()`: `shot:revokedevice` writes a fake trusted key into the real trust store, without the demo gate.** It calls `TombstoneTrustStore.add("abab…", label: "Demo reading tablet")` (Keychain-backed) and temporarily swaps the global `TombstoneSigning.now`. Nothing checks `DemoNetworkBlock.isActive` or the demo library, unlike Android's `seedShotDevice` (DEBUG && DemoNetwork.isActive). On a DEBUG build with a real sync folder the trust store keeps the extra device until it's revoked by hand. Narrow: it needs the launch argument. `prepareShot` (recovery copy files) is likewise ungated, but it only writes `.shot-recovery.json` files. Verified by reading.
- 7dc23568's `isPreview` reads `httpBodyStream` with a `hasBytesAvailable` loop. With a bound or streamed body that's still filling, it can read nothing and serve the work page instead of the preview. Demo only; noted, not a finding.
