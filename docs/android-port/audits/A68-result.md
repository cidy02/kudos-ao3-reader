## Gaps (Most Harmful First)

Ordered by user impact: **(1) User-made data that cannot be rebuilt** (pronunciations, imported original documents, custom fonts, soft-deleted user annotations/collections/queues) → **(2) Settings** → **(3) Metadata, caches, and envelope fields**.

1. **`pronunciations` (`global`, `fandoms`, `works`) — DROPPED by Android `.kudosbackup` import/export; conditional passthrough in Folder Sync; NOT COVERED with non-empty data in cross-platform tests**

### 3. Metadata, Caches, and Lifecycle / Envelope Fields

6. **`works[].lastAvailabilityCheck` — Merge parity bug on Android (`BackupMergeService.mergeWork` can drop non-null `lastAvailabilityCheck`)**
   - **iOS**: `Services/KudosBackup.swift:931,1007,1084,1161` merges `lastAvailabilityCheck` monotonically via `work.lastAvailabilityCheck = newest(work.lastAvailabilityCheck, archived.lastAvailabilityCheck)` (`Services/KudosBackup.swift:2472,4615`) regardless of which side wins LWW.
   - **Android**: `backup/BackupManifest.kt:71` and `backup/BackupMappers.kt:175,317` read and write `lastAvailabilityCheck`, and `REPLACE_LIBRARY` mode merges it via `maxInstant(existing.lastAvailabilityCheck, restored.lastAvailabilityCheck)` (`backup/BackupMergeService.kt:1256`), **but `BackupMergeService.mergeWork` (`backup/BackupMergeService.kt:781-864`) omits `lastAvailabilityCheck` from both `restored.copy(...)` (`:782-827`) and `existing.copy(...)` (`:829-864`)**. Consequently, in `RECONCILE` / `MERGE` modes, if the winning side has `lastAvailabilityCheck == null`, the losing side's non-null `lastAvailabilityCheck` is **dropped**.
