# Sync journal v9 wire format — D5 draft for review

Status: normative for framing, identity, admission, discovery and recovery; **pending D4** fields below are deliberately not frozen. This document implements plan § C and uses the reducers and semantics of `SYNC_OPERATION_MATRIX.md` (D4). A reader MUST reject an object it cannot authenticate or parse within bounds; it MUST retain admitted unknown operations verbatim. SwiftData and Room store the same logical bytes, independent of their database schemas.

## 1. Byte grammar and domains

All multi-byte integers are unsigned big-endian. `u8/u16/u32/u64` have their usual widths. `B[n]` is exactly n bytes; `V` is `u32 length || bytes`, maximum 16 MiB unless a smaller limit is specified. No padding, BOM, trailing bytes, duplicate JSON keys, NaN, infinities, lone surrogates or invalid UTF-8. Wire JSON is RFC 8785 JCS UTF-8; duplicate keys are rejected **before** canonicalization. A producer serializes and reparses to confirm canonical bytes. Strings use NFC except opaque user content, which is preserved exactly and compared by its UTF-8 bytes when D4 calls for canonical value ordering. JSON integers are exact signed 64-bit; decimal fractions are JCS numbers and may not be used for counters, sequence numbers or instants. `null` differs from absence. Map keys use Unicode scalar order as defined by JCS. No parser may silently coerce a type.

`UUID` is 16 RFC 4122 network-order bytes, with canonical lower-case hyphenated JSON spelling. `Hash` is 32 SHA-256 bytes, lower-case hex in paths and JSON. `KeyID = SHA256(raw Ed25519 public key)`; keys are 32 raw bytes, signatures 64 raw bytes. Library ID, writer incarnation and entity UUID are distinct UUID domains. Sequence and Lamport counter start at 1 and must not exceed `2^63−1`. A stamp is `(u64 counter, UUID incarnation, u64 seq)`, compared in that order by unsigned byte order; ties use the complete canonical op ID `(library UUID, incarnation UUID, seq)` bytes. An instant is signed 64-bit **milliseconds since Unix epoch UTC**, no leap seconds; source timestamps with finer precision are rounded to nearest millisecond, ties to even, before capture. ISO strings in D4 fixtures are semantic input, not wire timestamps. `RK-VALUE.pinnedAt` uses signed milliseconds for ordering; epoch-zero tuple components follow D4, and canonical value bytes are JCS.

The common immutable object envelope is `magic B[4] = 4b 4a 39 00 ("KJ9\0") | major u16=9 | minor u16=0 | type u8 | flags u8=0 | reserved u16=0 | payloadLength u64 | payload B[payloadLength] | sha256 B[32]`. Digest covers every preceding byte including header and payload. A keyed path uses this *whole-object* digest. Types: `1 bootstrap`, `2 admission`, `3 segment`, `4 checkpoint`, `5 blob`, `6 writer index`, `7 range index`, `8 digest bucket`. Unknown envelope types or nonzero flags are unsupported and never published as valid references. Maximum envelope payload: 16 MiB except blob (1 GiB); streaming readers still cap memory at 1 MiB.

Inside envelope types 1, 2, 4, 6–8 the payload is canonical JSON. Every such JSON object has `schema:9`, `libraryID`, and `kind` equal to its type name. Exact JSON property sets are given below; any unknown property is rejected at minor 0. Readers of a higher minor preserve the entire object but do not install it unless its `minReaderMinor` is supported. A higher major is never installed and causes `upgradeRequired`. Paths are advisory; object bytes and signed identities decide validity.

## 3. Record and signature preimages

A segment record is `u32 bodyLength | u16 kindCode | u16 recordFlags | bodyLength bytes canonical JSON | u16 signatureLength | signature`. `recordFlags` bit 0 means critical; other bits zero. Signature length is 64 for authority kinds and 0 otherwise. The body has exactly `{schema,libraryID,writer,seq,counter,kind,target,groups,payload,observed,requires,minReaderMinor}`; absent semantic values use `null` or empty map/list as appropriate. `groups` is a sorted array of `{id,critical,value}`; duplicate IDs fail. `requires` is sorted unique op IDs in canonical `(library UUID, writer UUID, u64 seq)` order, includes only **cross-writer semantic prerequisites**; same-writer prerequisites are implicit in contiguous prefix. `observed` contains capture evidence and named IDs per D4, not an admission shortcut. IDs are `{libraryID,writer,seq}`. A record's identity is its enclosing segment's library/writer and body seq; mismatch fails the segment. Unknown kind codes are admitted only with valid record framing and `minReaderMinor>0`; their complete record bytes, including signature, are retained. The receiver cannot project them or advance a prefix past a critical unknown kind.

Record digest is SHA256 of the entire record from `bodyLength` through signature. The **segment** signs the digest and exact range (§5), binding ordinary records to the admitted writer key. Record digests are retained for equivocation detection. Authority records additionally sign `Ed25519("Kudos-v9-authority\0" || u16(kindCode) || u32(bodyLength) || canonicalBody)`. This is the DEC-11 preimage: every semantic field, full stamp, scope, basis, identity tiers, evidence digest, head and subject is inside canonicalBody. A receiver rejects an authority record with a missing or invalid 64-byte signature before D4 authorization evaluation. `administrative:true` on a restore is pending D4; no unsigned narrowing is accepted.

`canonOpId` for DEC-21 is the ASCII lower-case UUID spelling of library, a `/`, writer, a `/`, and base-10 seq with no leading zero. UUIDv5 input is UTF-8 `"kudos-v9-annotation/" || canonOpId || "/" || sourceUUIDlower`, under UUID namespace `5c35a74e-5fdc-5bc2-95f3-94692346b83d`. D4's existing annotation UUID vectors MUST be checked against this proposed domain before freeze; until then this namespace is **pending D4**, and an implementation may not mint dedupe IDs from it. DEC-26 font folded name uses Unicode Default Case Folding (full mapping) after NFC, then NFC again, with Unicode version 15.1; split extension at the final U+002E after the last path separator, treating leading-dot names without a second dot as no extension. Reject slash, backslash, NUL and control characters in display names. Allocator stamp order is ascending. Unicode table/hash and Android/Apple conformance vectors are needed before freeze.

## 4. Bootstrap, admission and version negotiation

Root is `kudos-sync-v9/<library-uuid>/`. The immutable bootstrap at `bootstrap/<hash>.boot` contains `{schema,kind,libraryID,sourceV8ManifestSHA256,checkpointHash,founders:[{keyID,publicKey}],creatorWriter,createdAt,bootstrapNonce,minReaderMinor,signature}`. Founders sorted by key ID, nonempty. `createdAt` is wire instant; nonce is 32 random bytes. `signature` is creator founder Ed25519 over `"Kudos-v9-bootstrap\0" || SHA256(canonical JSON with signature:null)`. A mutable `bootstrap/HEAD` is only a hint containing the bootstrap digest. Join scans bounded bootstrap candidate pages (§5), verifies each immutable descriptor and checkpoint closure; if two valid descriptors for one library differ in any signed byte, stop with `bootstrapConflict`. Rerunning setup reuses the same nonce, bytes and object hash recorded in the local setup journal. A second initializer cannot overwrite one. The legacy v8 folder remains untouched. Source manifest digest identifies the validated and folded v8 input; no legacy write is silently imported after cutover.

`admissions/<writer-uuid>/<hash>.adm` contains `{schema,kind,libraryID,writer,writerPublicKey,writerKeyID,authorKeyID,authorityHead,enrollOpId,createdAt,minReaderMinor,signature}`. Signature by author key covers `"Kudos-v9-admit\0" || SHA256(canonical JSON with signature:null)`. Founder's first writer uses `authorityHead:"root:<keyID>"`, `enrollOpId:null`; other writers name a valid D4 `writer.enroll` op and its head. Admission is valid only if author authority at enrollment stamp is valid; no free-standing admission grants purge authority. Reinstall/restore MUST mint a new writer UUID and key pair. An admission fixes one key per writer forever; conflicting keys halt that writer. Signature verification of segment commits uses this key, even after authority revocation (DEC-9 content remains valid). A writer with no verified admission is pending, not applied.

Readers advertise supported `(major,minor)` locally; there is no negotiated mutable server state. A writer may publish minor 0 only after its peer floor is known or the owner accepts upgrade-required peers. A higher-minor object is kept byte-for-byte and its descriptor indexed, with no mutation of signed bytes. Unknown noncritical ops/groups are retained and included in checkpoint opaque closure; critical unknowns block apply at that sequence. An old reader never republishes a rewritten segment or checkpoint it cannot interpret.

## 5. Segments and bounded discovery

Segment payload: `headerLength u32 | canonical header JSON | recordCount u32 | records | trailer`. Header exactly `{schema:9,kind:"segment",libraryID,writer,firstSeq,lastSeq,firstCounter,lastCounter,requiresDigest,minReaderMinor,admissionHash}`. `requiresDigest` is SHA256 of sorted unique cross-writer requires IDs encoded as concatenated 40-byte op IDs. `recordCount = lastSeq-firstSeq+1`, 1–4096. Each record has the next seq, strictly increasing counter and same library/writer. Trailer is `SHA256(all payload bytes before trailer) B[32] | writer signature B[64]`; signature preimage is `"Kudos-v9-segment\0" || libraryUUID || writerUUID || u64(firstSeq) || u64(lastSeq) || trailerHash`. Outer envelope digest then covers the complete payload. A missing/bad trailer is pending or invalid; never applied. Path `segments/<writer-uuid>/<firstSeq:020d>-<lastSeq:020d>-<outer-hash>.seg`. At one `(writer,seq)`, two verified record digests mean equivocation: halt entire incarnation, retain both byte sets and report; do not choose by hash order. Exact duplicate bytes are idempotent. A gap blocks the contiguous applied prefix and downstream same-writer records, with durable `(writer,missingSeq)` pending state.

Discovery is a fixed 256-shard directory by first byte of SHA256(writer UUID). `writers/<hh>/<writer-uuid>/<hash>.idx` is an immutable signed writer index JSON `{schema,kind:"writerIndex",libraryID,writer,admissionHash,rangePages:[hash],highSeq,signature}`. Its signature covers domain `Kudos-v9-index\0` and canonical JSON with signature null. A writer publishes a new index only after segment publication; a stale index never proves absence. Range pages at `ranges/<writer>/<firstSeq:020d>-<hash>.idx` contain max 1024 sorted `{first,last,segmentHash}` entries and a `nextPageHash` or null; an authenticated signed root index pins each page hash. A reader points directly at the page covering its `nextSeq` using sorted page first keys and opens at most one page plus one adjacent page per writer per poll. Listing shards is bounded by 256 directory checks plus one page of 256 writer names per poll, with a persisted scan cursor; discovering more writers continues next poll. Discovery is a liveness hint; absent pages cause retry, never a negative conclusion. No-op cost is O(256 + active writers), independent of retained segments. Hash object lookup uses `aa/bb/<hash>` sharding for checkpoints and blobs; a digest is opened by path, never by whole-directory listing.

## 6. Dependency admission, checkpoints and replay

Every received record is written to a bounded durable inbox with original bytes, source object hash, dependency IDs and status `unverified|admitted|gap|requires|unsupported|invalid|applied`. Verification and admission precede projection. Named same-writer references resolve from prior contiguous ops; cross-writer `requires` resolve through an applied op or an installed checkpoint typed-evidence index. On an uncovered ID, wait; on covered wrong-kind/owner/class, emit the D4 diagnostic and advance only according to D4's invalid-command rule. Recheck pending on op arrival, new segment/index, or checkpoint install. Persist projected facts, diagnostics, applied vector, Lamport maximum, inbox disposition and outbox cursor in one database transaction. A failed transaction retries unchanged bytes. Never echo remote apply to the outbox.

Checkpoint payload is canonical JSON `{schema:9,kind:"checkpoint",libraryID,cut,logicalCounter,retained,evidence,diagnostics,opaque,assetClosure,minReaderMinor}`. `cut` is sorted `{writer,seq}`; absent writer means zero. `retained` is sorted `{originalKey,reducer,group,summary}`; reducer is one of the 17 closed D4 `RK-*` names. `evidence` is sorted typed tuples `{opId,kind,originalOwner,group,valid,stamp,sourceEpoch,class,scope}` with null for inapplicable fields. `opaque` contains base64url unpadded exact records plus their source segment hash and semantic references. `assetClosure` is sorted `{digest,size,kind,owner}`. **The `summary` schemas and their exact projection evidence are pending D4 cleanup** (rank, Q2/L1/T2/S1/P3 and fixture mismatches). Until frozen, checkpoint creation/install is disabled; a fixture here exercises the envelope and structural round trip only. A future schema revision MUST specify every reducer summary shape and test `project(retain(prefix)+suffix)==project(all)` including intermediate pending. A cut is valid only when causally closed; each covered reference has matching typed evidence. No checkpoint can assert a cut beyond verified contiguous sequences.

Install: stream-verify immutable checkpoint, all required referenced objects and opaque closure; stage in a shadow generation; preserve current applied facts and all local reserved bytes outside its cut; write a durable install intent; atomically activate state, cut, logical maximum and mutation cursor in one store transaction, then retire the intent. A crash before activation keeps the old generation; after activation resumes from the new. Asset files have a separate recoverable installation journal (§7).

For incomparable cuts A and B, choose the candidate with greatest total covered operations `sum(seq)`, then lexicographically greatest sorted cut vector, then lowest checkpoint hash. This deterministic choice is an optimization, not a merge: replay every locally applied operation outside the chosen cut in original bytes (including those covered only by the discarded cut), then every new suffix. Preserve reserved unpublished segment bytes and IDs; never renumber them. Unreserved local intents are re-evaluated against the newly projected state before minting. If replay lacks any required original segment/opaque bytes, refuse installation and keep the prior state. This addresses `f1` without pretending vector max is a published checkpoint.

## 7. Blobs, restart and limits

Blob envelope type 5 payload is `u64 rawLength | raw bytes | SHA256(raw bytes) B[32]`. Path `blobs/<digest[0:2]>/<digest[2:4]>/<digest>.blob`, where digest is SHA256(raw bytes), not envelope hash; outer envelope still verifies framing. Blob references are `{digest,size,mediaType,owner,assetKind}` with exact digest and size. All asset groups may apply metadata with an explicit pending reference; **no D4 atomic reducer group waits for bytes**. `available` is a separate local materialization state after size/digest check, same-volume staged file replacement, recoverable file journal and database availability commit. Keep prior verified EPUB readable until replacement commits; cancellation after commit reports success. Font selection can point at a pending font and UI uses fallback until verified bytes arrive. Blob and segment reclaim remain disabled.

Writer reservation states: `draft → reserved → published → observed`; reserve `(seq range, counter range, complete bytes, object hash)` durably before upload. Ambiguous upload retries identical bytes. On restart, a reserved object is republished first. Receiver states: `downloaded → verified → admitted → applied`, with `pending` variants from §6. Checkpoint install states: `staged → verified → activation-intent → active → cleaned`. A crash resumes the recorded state and checks hashes; it never guesses from a filename. Bootstrap uses the same rule. Asset install states: `staged → verified → replacement-intent → switched → available`; after any crash, verify the chosen file and finish or roll back to the previous verified file.

D7 provisional device budgets, subject to measured adjustment: max 256 MiB pending inbox or 100,000 pending records, max 30 days oldest unresolved dependency before surfaced repair, max 2 GiB reserved unpublished bytes, max 64 GiB locally cached retained immutable objects. At 80% quota, pause download and publication and show storage pressure; local commands and transactional outbox continue if database space remains. At 100%, reject new sync publication reservations but do not delete local edits. A 30-day age is an alert, not permission to skip a gap. Retained remote objects are never pruned under these quotas. D7 measures no-op, normal delta, bootstrap and offline catch-up and revises limits before release.

## 8. Open D4/owner gates

Before calling this a frozen interoperable v9 format: D4 cleanup must settle the pending fields in §§2, 3, 6; verify the UUIDv5 and Unicode vectors against both platform libraries; specify every reducer summary schema and golden replay for it; review the proposed quotas against D0 device data. Owner decisions needed: key recovery/pairing UX and whether a writer that has reached local sync storage pressure may continue accepting unbounded offline edits. No app code may emit this format until those gates pass.
